# RTD data stores

RTD has no verified public checkpoint, archival, or snapshot service. The Sui
bucket names and hostnames inherited from upstream do not identify RTD data.
Do not use them to bootstrap or restore an RTD node.

## Choosing a store

First verify the genesis digest and chain ID of the network you operate. Then
configure a store populated by that same RTD network. Set credentials and
retention according to your own infrastructure.

## Checkpoint remote stores

### GCS buckets (full retention, Requester Pays) {#checkpoint-gcs}

Supply a GCS bucket only after your operator has published RTD checkpoints to
it and confirmed the billing and access policy. No RTD GCS bucket is provided
by this source tree.

### S3 bucket (full retention, Requester Pays) {#checkpoint-s3}

Supply an S3 bucket only after verifying that it contains checkpoints for your
RTD chain ID. No RTD S3 bucket is provided by this source tree.

### HTTPS endpoints {#checkpoint-https}

Set an HTTPS endpoint explicitly if your operator runs one. Confirm its chain
ID and retention before using it for recovery or backfill. There is no default
public RTD checkpoint endpoint.

## Snapshot stores

### Formal snapshot HTTPS endpoints {#formal-https}

Use a snapshot endpoint only after checking its chain ID and snapshot hash
against a trusted RTD operator. No public endpoint is configured.

### Formal snapshot buckets {#formal-buckets}

Use an operator-owned bucket with verified RTD snapshots and credentials.

### Formal snapshot free bucket {#formal-free}

No public RTD free snapshot bucket has been verified.
