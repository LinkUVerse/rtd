A high-level comparison of the SDKs available for building on Rtd, to help you choose the right kit for your language, platform, and use case.

This page provides a high-level comparison of the SDKs available for building on Rtd. Use it to find the kit that best matches your language, platform, and use case. For links to each SDK and a fuller list of community projects, see [Rtd and Community SDKs](./rtd-sdks.mdx).

:::info Contribute to this page

This comparison currently lists the SDKs maintained by LinkU Labs. If you maintain a Rtd SDK and want to add it, contributions are welcome. See [Add your SDK](#add-your-sdk) for how to submit a row.

:::

## Rtd SDKs

The following SDKs are developed and maintained by LinkU Labs.

| SDK | Language / platform | Maintainer | Primary use case | Transport | Status |
| --- | --- | --- | --- | --- | --- |
| [TypeScript SDK](https://sdk.linkuverse.com/typescript) | TypeScript / JavaScript | LinkU Labs | General-purpose client for building apps, scripts, and services | gRPC (recommended), GraphQL, JSON-RPC (deprecated, do not use) | Stable |
| [dApp Kit](https://sdk.linkuverse.com/dapp-kit) | TypeScript / React | LinkU Labs | Web frontends: wallet connection, hooks, and UI components | Builds on TypeScript SDK | Stable |
| [Rust SDK](https://github.com/LinkUVerse/rtd-rust-sdk) | Rust | LinkU Labs | Backend services and high-performance clients | gRPC | Active development |
| [zkSend SDK](https://sdk.linkuverse.com/zksend) | TypeScript | LinkU Labs | Creating and claiming zkSend links and Stashed functionality | Builds on TypeScript SDK | Stable |
| [DeepBookV3 SDK](../onchain-finance/deepbook/deepbookv3-sdk/deepbookv3-sdk.mdx) | TypeScript | LinkU Labs | Interacting with the DeepBook onchain order book | Builds on TypeScript SDK | Stable |

## Choosing an SDK

- **Building a web app or wallet integration?** Start with the [dApp Kit](https://sdk.linkuverse.com/dapp-kit), which builds on the TypeScript SDK and adds React hooks and components for wallet connection.
- **Writing scripts, services, or a Node.js backend in TypeScript?** Use the [TypeScript SDK](https://sdk.linkuverse.com/typescript) directly. Prefer its gRPC client (`RtdGrpcClient`) for new projects; the JSON-RPC client is deprecated.
- **Building a performance-sensitive backend in Rust?** Use the [Rust SDK](https://github.com/LinkUVerse/rtd-rust-sdk) (gRPC).
- **Working with DeepBook or zkSend?** Use the purpose-built [DeepBookV3 SDK](../onchain-finance/deepbook/deepbookv3-sdk/deepbookv3-sdk.mdx) or [zkSend SDK](https://sdk.linkuverse.com/zksend), which layer on top of the TypeScript SDK.
- **Need another language (Python, Go, Kotlin, Swift, Dart, Vue)?** See the community SDKs on the [Rtd and Community SDKs](./rtd-sdks.mdx#community-sdks) page.

## Add your SDK

This comparison is intended to grow with the ecosystem. If you maintain a Rtd SDK, you can add it to a future "Community SDKs" comparison table by opening a pull request against the [Rtd repository](https://github.com/LinkUVerse/rtd).

When you submit a row, please include the following so the comparison stays consistent and useful:

| Column | What to provide |
| --- | --- |
| SDK | Name of the SDK, linked to its documentation or repository. |
| Language / platform | The primary language(s) and platform(s) the SDK targets. |
| Maintainer | The individual or organization that maintains the SDK. |
| Primary use case | A short phrase describing what the SDK is best suited for. |
| Transport | The API the SDK uses to communicate with Rtd (for example, GraphQL, JSON-RPC, gRPC), or the SDK it builds on. |
| Status | The maturity of the SDK (for example, Stable, Active development, Maintenance, Experimental). |

For guidance on contributing to Rtd documentation, see [Contribute to Rtd](./contribute/contribution-process.mdx) and the [Style Guide](./contribute/style-guide.mdx).

:::info

Maintenance and community support vary. Research a project's history and support level before committing to using its utilities.

:::
