A CI job can build and test a Move package against a reviewed RTD source
revision. It should not publish to a public network until that network's
chain ID, RPC endpoint, CLI release, funded signer, and upgrade policy have
been verified.

Build the CLI from this repository and check the version:

```sh
cargo build -p rtd
./target/debug/rtd --version
```

Then run the package checks using that binary from the package directory:

```sh
/path/to/rtd move build
/path/to/rtd move test
```

Pin the exact RTD source commit in the workflow. A branch name can advance
between CI runs and change the framework bytecode or CLI behavior. Keep signing
keys out of CI logs and artifacts. A publish job should target an explicitly
configured RTD RPC endpoint and confirm its genesis digest and chain ID before
sending any transaction. Require operator approval for an irreversible package
publish or upgrade.

The previous version of this page used an upstream `suiup` repository and
unverified Testnet/Mainnet releases. Those commands have been removed because
this fork has no verified public installer or network-specific binary release.
