# Ledger 发布边界迁入

发布范围与数据读取规则落在正式 `rtd-kv-rpc` / `rtd-kvstore`，归档Rust网关负责新鲜发布证明，Shell只编排。当前基础实现对应R4.01，未代表完整端到端迁移验收。

请求的 `x-rtd-visible-checkpoint` 由可信入口覆盖并注入。仅接受唯一规范u64；没有header保留内部原生调用。服务不把该数字本身当作密码学证明，公共部署仍必须经认证guard且不能直连绕过。

当前已接入的基础路径：

| 路径 | 基础行为 |
|---|---|
| List检查点、交易、事件 | 扫描前将exclusive上界收紧到发布inclusive上界加一，与索引上界相交；u64最大值不溢出 |
| Get/Batch交易 | 即使只读digest，也读取并检查交易所在检查点；缺失或重复来源列不能默认为创世 |
| Get检查点 | latest受上界限制，显式高度/digest读取后检查summary；缺少来源证明拒绝 |
| GetServiceInfo | 带发布上界的请求直接读取所需流水线共同保留范围及目标summary，不把最新缓存冒充历史信息 |
| GetEpoch | 限制可读epoch，尚未发布的epoch结束字段隐藏，缺少或不一致的来源字段拒绝 |
| Get/Batch对象 | 选择发布高度以内的版本，核对对象键/内容及生成交易effects；批量读取有界并保留单项结果 |
| 包和类型解析 | 按已发布package metadata固定历史版本；请求独享resolver及其缓存，避免最新布局污染历史查询 |
| 历史包选择 | Version和AtCheckpoint核对升级谱系、来源检查点、准确对象版本及包内容，未来或缺失版本不能落回latest |
| JSON与嵌套查询 | 显式请求JSON时布局缺失、数据损坏或大小超限返回错误；检查点内嵌交易/对象复用单点解析与mask，检查交易高度/时间一致性 |
| 批量交易非法输入 | 非法digest保留为原位置的单项InvalidArgument，不吞掉其他合法结果；全非法请求不发起存储读取，批量上限仍生效 |

依赖错误转换保留已分类的RPC状态和结构化details，三类暂态依赖故障保持可重试语义；Unknown仅在带指定类型的连接错误时转换，不能依赖消息文本。服务信息缓存记录采样起点，1秒后过期；后台失败同时清除缓存和既有单调读取视图，缺失/过期时读取当前水位。

普通与admitted服务信息共用一次批量读取得到的全流水线范围交集。下界取最大reader_lo，上界取最小处理高度；缺失、损坏、重复配置或无交集拒绝成功范围，不能把历史下界伪造为0。存储层原有最小整行水位接口保持原语义。

上述基础及依赖分支已通过166项Ledger库回归，RPC API208项回归通过；MockBigtableServer和库测试不代替真实服务/后端接线验收。后续仍需所有路径的原生RPC与实际后端验证、入口无法旁路及完整生命周期。证据由迁移日志91/92记录，不能提前勾选整包。

数据列校验的变化拒绝缺失、重复或损坏的来源字段；不升级存储schema，不写业务表，不修改现行数据库。源补丁、移植摘要和测试结果由部署工程工作日志记录；Rust实现和测试仅在正式工程中维护。

## 等待首次创世检查点

Ledger 必须取得 KV 中的检查点 0 才能确定链身份并开放监听。首次同时启动 KV 写者和 Ledger 时，成功读取但尚无检查点 0 会在 Rust 内按 100ms 间隔重试；`genesis-wait-timeout-ms` 是包含读取和等待的单一总预算，默认 30000ms，显式范围 1～300000ms。配置无效在连接中间件前拒绝；超时返回错误，不开放 gRPC 或健康监听，不初始化表、发身份或改写数据。

只有检查点缺失会等待。认证、连接、解码错误和缺失 summary 立即失败；不自动改变地址、降低 TLS 或从其他来源读取。旧 `KvRpcServer::new` 保持调用接口，使用默认预算；新 `new_with_genesis_timeout` 允许调用者传入固定预算。此等待不代替 14 管道水位、完整 readiness 或写者任期协调验证。
