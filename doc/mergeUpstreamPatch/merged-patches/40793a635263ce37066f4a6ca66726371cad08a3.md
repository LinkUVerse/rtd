## 基线关联

Tidehunter 依照 table struct 的字段顺序分配 keyspace。fork 基线把 `full_checkpoint_content_v2` 和 `deferred_transactions_with_aliases_v2` 插入既有列表中间，会改变其后所有表的编号，而 Tidehunter 当前不支持这种 schema 演进。

## 移植内容

- 把两个新表移到各自 table struct 末尾。
- RTD 仍实际使用 `authority_capabilities` V1 表，因此没有照搬上游依赖另一项 dead-branch cleanup 的条件编译 hunk。
