# dbd8cfa7：在生成交易输出前合并 accumulator events

- 上游提交：`dbd8cfa70a222975ec3613eb3e552557742ad32d`
- RTD 提交：`aca95a578a822552524732a8c908c71f69b2cb50`
- 上游标题：`Merge accumulator events early to avoid discrepancy between TransactionOutputs::accumulator_events and TransactionEffects::acumulator_events (#24762)`

## 基线关联

fork 基线已经包含 accumulator event 生成和 `TemporaryStore::merge_accumulator_events`。原实现先把同一 accumulator object 的多次写入原样放入 `ExecutionResults` 和 `TransactionOutputs`，只在构造 `TransactionEffects` 的 object changes 时晚合并。

因此 CheckpointBuilder 落后于 CheckpointExecutor 时，两条路径可能分别看到未合并 events 和已合并 effects，形成状态差异并导致 validator fork。相关生成和晚合并逻辑在 RTD 中原样存在。

## 移植内容

- programmable transaction execution 按 accumulator object ID 对 events 分组，并用 `AccumulatorWriteV1::merge` 在返回 `ExecutionResults` 前合并。
- `TemporaryStore` 构造 effects object changes 时直接使用已经合并的 event，删除晚合并路径。
- 增加回归测试，验证两个指向同一 accumulator 的写入离开执行层前已经合为一个净写入。
- 所有类型和路径使用 RTD 品牌映射。

## 红绿验证

修复前回归测试因早期合并函数不存在而编译失败。修复后：

```text
cargo test -p rtd-adapter-latest accumulator_events_are_merged_before_leaving_execution --lib
1 passed; 0 failed

cargo test -p rtd-adapter-latest --lib
2 passed; 0 failed
```

既有 `test_multiple_deposits_merged_in_effects` 两次都在执行待测多写入交易之前失败：初始单笔 deposit 返回后，fullnode child-object resolver 尚未看到 accumulator value。失败位置是既有的 `Accumulator value should have been created` 前置断言，不是本补丁新增的合并断言。
