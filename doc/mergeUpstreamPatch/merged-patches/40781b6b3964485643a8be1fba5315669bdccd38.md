# 40781b6b：在 barrier 执行后结算 object funds

- 上游提交：`40781b6b3964485643a8be1fba5315669bdccd38`
- RTD 提交：`161f14e5c8ba051d3bc9a772bc3859b7116c0248`

## 基线关联

fork 基线只从 checkpoint builder 结算 object funds；若节点已进入下一 epoch、没有机会运行该 builder，scheduler 会永久等待。把结算提前后，settled version 可能领先待调度交易，旧断言又会 panic。

## 移植与验证

barrier settlement transaction 执行后立即推进 object-funds version；address funds 仍由 checkpoint builder 结算。scheduler 新增 `last_scheduled_accumulator_version`，以实际调度版本跨 commit 清理 pending withdraw，并允许 settled version 领先。

上游两个回归测试先移植：修复前 `test_settle_ahead_of_schedule` 以 `accumulator_version 0 < last_settled_version 1` panic，修复后均通过。
