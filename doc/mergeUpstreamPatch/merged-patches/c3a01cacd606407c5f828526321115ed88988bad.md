# c3a01cac：隔离 consistent-store gRPC 请求 panic

- 上游提交：`c3a01cacd606407c5f828526321115ed88988bad`
- RTD 代码提交：`61284b0b331d57956d5cedb9da8df459ee6bf484`
- RTD Docker 集成提交：`6c2ddedd437865b88c4258a0de4e487bc032667a`
- 上游标题：`consistent-store: raise internal error for panics`

## 基线关联

fork 基线和 RTD 的 consistent-store router 没有捕获 service future panic。请求处理 panic 因而不能被转换为 gRPC error，并与默认 abort release profile 组合成进程级故障。

## 移植内容

- 新增使用 `FutureExt::catch_unwind` 的 Tower layer/service/future。
- panic 响应转换为 `tonic::Status::internal` HTTP 响应，保留字符串 payload。
- 增加 `consistent_rpc_requests_panicked` 指标。
- Docker 使用 unwind profile 和对应产物目录。
- 增加 panic 转换与正常请求透传两个单测。
