# 5461f7c4：consistent store 写入同步落盘

- 上游提交：`5461f7c462f13aa2215119acaf3b68a7b1a3d0cf`
- RTD 提交：`77784dc7e6494c5be5c6c9a15095256eae1cbb10`

## 基线关联

RTD 的其他 RocksDB 写路径已启用 fsync，但 consistent store 的 watermark 和 restore batch 仍用非同步写入。进程确认进度后发生崩溃或掉电时可能回退持久化状态。

## 移植与验证

四个持久化入口改用 `write_opt` 和统一的 sync write options。该耐久性条件不能稳定模拟掉电，使用现有 DB/restore 测试验证行为：

```text
cargo test -p rtd-indexer-alt-consistent-store --lib
48 passed; 0 failed
```
