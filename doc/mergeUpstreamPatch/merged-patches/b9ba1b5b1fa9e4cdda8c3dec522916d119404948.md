# b9ba1b5b：alias versions 按签名顺序排列

- 上游提交：`b9ba1b5b1fa9e4cdda8c3dec522916d119404948`
- RTD 提交：`91c5f4d3803e31ce9a634177c3a6df5b3344e838`

## 基线关联

fork 基线 checkpoint contents 将 required-signer 顺序的 alias versions 与实际 user-signature 顺序直接 `zip`。sponsored transaction 的签名可合法重排，因此会把 version 绑定到错误签名。

## 移植与验证

上游实现依赖 post-fork TransactionClaim。RTD 保留基线 `WithAliases<(RtdAddress, Option<SequenceNumber>)>` wire type，让签名验证返回 signer 到 signature 的索引并把 alias versions 重排到实际签名顺序；缓存同时保存该映射。
