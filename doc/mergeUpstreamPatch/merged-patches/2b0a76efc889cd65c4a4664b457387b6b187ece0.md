# 2b0a76ef：在 Move IDE hover 中保留字符串常量原文

- 上游提交：`2b0a76efc889cd65c4a4664b457387b6b187ece0`
- RTD 提交：`4b82d050ae81a3b611e889219edbda85dbdf5896`
- 上游标题：`[move-ide] Better on-hover value display for string constants (#24704)`

## 基线关联

fork 基线的 compiler analysis 已在 `CompilerAnalysisInfo::string_values` 中保存 byte string 和 hex string 的源码形式，但 Move analyzer 构造常量 hover 时只遍历降级后的表达式。因此 `b"hello world"` 显示为十一个十进制字节，`x"DEADBEEF"` 显示为四个十进制字节。RTD 保留相同的数据和缺失使用路径。

## 移植内容

- 让 compiled/cached package 始终携带 `CompilerAnalysisInfo`，无编译结果时使用空值。
- 增量编译合并时同步保留和更新 `string_values`。
- 构造常量 hover 时优先按表达式位置读取保存的字符串原文，再回退到既有 best-effort 转换。
- 更新 hover 快照，并修正同一测试附近的既有注释拼写；保留 RTD 的 `rtdte` 品牌命名。

## 验证

基线快照明确记录旧输出为十进制字节数组。修复后，为外部 Move workspace 临时补充被品牌替换破坏的自定义 test path（未提交）并运行：

```text
cargo test --manifest-path external-crates/move/Cargo.toml \
  -p move-analyzer --test ide_testrtdte consts
1 passed; 0 failed
```

新快照分别显示 `b"hello world"` 和 `x"DEADBEEF"`。精确源码的 `rustfmt --check` 仅报告 RTD 基线既有的 `IMPLICIT_STD_*`/`IMPLICIT_RTD_*` import 排序差异，未引入全文件格式化噪声。
