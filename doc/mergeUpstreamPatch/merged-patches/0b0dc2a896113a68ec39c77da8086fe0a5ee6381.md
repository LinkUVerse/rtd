# 0b0dc2a8：修复总供应量 off-by-one

- 上游提交：`0b0dc2a896113a68ec39c77da8086fe0a5ee6381`
- RTD 源码提交：`a3efb2806ee49cdcd22e13a55de69ab9e628b0a2`
- RTD 协议 105 快照提交：`ff28c61c303253d8cec3618b2d32c1021a1e4fb1`
- 上游标题：`[framework] fix off-by-one error in total supply (#24702)`

## 基线关联

fork 基线与 RTD 的 `balance::increase_supply` 都使用：

```move
assert!(value < (18446744073709551615u64 - self.value), EOverflow);
```

严格小于会拒绝总供应量恰好达到 `u64::MAX` 的合法操作。这是 fork 前既有代码的直接算术边界错误。

## 移植内容

- 改为 `value <= (std::u64::max_value!() - self.value)`。
- 增加达到 `u64::MAX` 成功、再增发 1 以 `EOverflow` 失败的 Move 单测。
- 更新生成的 `docs/rtd/balance.md` 和 `packages_compiled/rtd-framework`。
- 将上游事务边界测试中的 `u64::MAX - 1` 更新为 `u64::MAX`，同步两个快照。
- RTD 固定使用协议 105 字节码快照，因此按仓库既有流程重建 105 的 `0x2` 框架包、manifest 和 genesis 快照。manifest 指向实际源码提交 `a3efb280...`。
- 所有模块、路径和类型使用 `rtd`/`RTD`/`Rtd` 品牌映射。
