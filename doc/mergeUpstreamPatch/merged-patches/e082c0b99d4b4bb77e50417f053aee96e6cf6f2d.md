# e082c0b9：publish/upgrade 尊重显式 sender

- 上游提交：`e082c0b99d4b4bb77e50417f053aee96e6cf6f2d`
- RTD 提交：`e9a53b8d0c8e3184d44f036e1d7cdbe75ec2aad9`

## 基线关联

fork 基线已公开 `--sender`，但 publish 和 upgrade 在构造交易前始终从 gas 推断 sender，导致序列化交易和 UpgradeCap recipient 使用错误地址。

## 移植与验证

回归测试修复前观察到交易 sender 与指定地址不同；现优先使用 `processing.sender`。

```text
cargo test -p rtd --test cli_tests test_publish_sender_flag_respected_in_serialized_transaction
1 passed; 0 failed
```
