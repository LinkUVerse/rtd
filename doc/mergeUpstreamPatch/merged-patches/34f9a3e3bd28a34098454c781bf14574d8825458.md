# 34f9a3e3：为 Move 调用分析行补充命令索引

- 上游提交：`34f9a3e3bd28a34098454c781bf14574d8825458`
- RTD 提交：`2e63c3c394b3dbf2745cfe37780f44a174c762b0`
- 上游标题：`Add missing call index column to move calls table (#24724)`

## 基线关联

fork 基线和 RTD 的 `TransactionDataAPI::move_calls()` 只返回 `(package, module, function)`。同一个 PTB 可以多次调用同一函数，分析索引据此产生重复行，无法用交易摘要和调用信息唯一定位命令。上游 PR 明确记录该问题会导致 Dune 和内部查询错误。

## 移植内容

- `rtd-types` 在遍历 PTB commands 时使用 `enumerate()`，返回 `(cmd_idx, package, module, function)`。
- `rtd-analytics-indexer` 的 `MoveCallEntry` 增加 `cmd_idx: u64` 并写入 parquet 行。
- `rtd-core`、legacy indexer、indexer-alt 和 JSON-RPC filter 解构并忽略不需要的索引，保持原有查询语义。
- 增加含有非 MoveCall 命令夹层的回归测试，确认返回的是原始 PTB 命令位置 `0` 和 `2`，而不是过滤后的序号。
- 路径和类型全部使用 RTD 品牌映射。
