# da34bd87：始终保留全零的必需 Nitro PCR

- 上游提交：`da34bd879b8e53a67f9955a393bd5c5ceede94db`
- RTD 提交：`e25a00e95f31e4008f5e522406ded0e6bd8bb706`
- 上游标题：`[fix] add always_include_required_pcrs flag to parse nitro attestation (#24670)`

## 基线关联

该提交修复上游 `#24214` 引入的回归。`#24214` 对应提交
`ad898dbaca65a7a01832c912dfd7a5e1994a0b9f` 是 fork 基线
`35d0fac50adb310ca9049af5a933336adeaac468` 的祖先。

基线在 Devnet/Testnet 启用 `include_all_nonzero_pcrs` 后，会过滤所有全零 PCR，连 AWS
要求的 PCR 0-4 和 8 也会被过滤。这与旧解析模式始终保留必需 PCR 的行为不一致。RTD
保留了相同的解析条件和协议配置，因此缺陷直接适用。

## 移植内容

- 为 Nitro 解析器增加 `always_include_required_pcrs` 参数。
- 当新参数开启时，PCR 0-4 和 8 无论是否全零均保留；自定义 PCR 仍只保留非零值。
- 在协议版本 105 的 Devnet/Testnet 配置中开启新行为，Mainnet 和旧版本保持不变。
- 将配置项传入最新 Move native，并同步 RTD framework 文档、OpenRPC 和协议快照。
- 增加 Rust 和 Move 回归覆盖，确认全零 PCR 3、8 与非零自定义 PCR 16 的组合行为。
