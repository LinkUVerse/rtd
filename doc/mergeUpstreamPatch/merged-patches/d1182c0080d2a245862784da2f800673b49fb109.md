# d1182c00：隔离 GraphQL 请求 panic

- 上游提交：`d1182c0080d2a245862784da2f800673b49fb109`
- RTD 代码提交：`9047fc5012a663f94ae6b37a452177b51b213a5b`
- RTD Docker 集成提交：`6c2ddedd437865b88c4258a0de4e487bc032667a`
- 上游标题：`graphql: raise 500 for panics`

## 基线关联

fork 基线和 RTD 都没有在 GraphQL HTTP service 边界捕获 resolver panic，而且默认 release profile 使用 `panic=abort`。因此单个请求中的 panic 会中断连接或终止整个 RPC 进程，而不是向该请求返回 internal error。

## 移植内容

- 新增继承 `release`、但使用 `panic=unwind` 的 `release-unwind` profile。
- GraphQL router 增加自定义 `CatchPanicLayer`，把 panic payload 转为带 `INTERNAL_SERVER_ERROR` code 的 GraphQL 500 响应。
- 增加 `graphql_queries_panicked` 指标。
- RPC Docker 默认构建 unwind profile，并从对应 profile 目录复制产物。
- 增加真实 HTTP resolver panic 回归测试。

## 红绿验证

修复前测试先因 `RpcMetrics` 不存在 `queries_panicked` 字段而编译失败。修复后：

1 passed; 0 failed
