# 0662e882：首次进程启动始终执行自有块恢复

- 上游提交：`0662e8825c8c02e7e63b3014acfd05a9058a8345`
- RTD 提交：`d97eace1dbb93f7b8bf8db9649801d2081a2e454`
- 上游标题：`[consensus] recover own blocks regardless of whether blocks have been accepted in the epoch (#24698)`

## 基线关联

fork 基线和 RTD 都只在以下三个条件同时满足时执行 amnesia recovery：进程内 `boot_counter == 0`、`highest_accepted_round() == 0`、恢复超时非零。

进程首次启动时需要从其他验证节点恢复最后的自有提议块，以避免本地最后提议块缺失导致 equivocation。数据库中已经接受其他块并不证明最后的自有块完整，因此 `highest_accepted_round() == 0` 会错误跳过恢复。

## 移植内容

- 移除对 `dag_state.read().highest_accepted_round()` 的判断。
- 保留 `boot_counter == 0` 和恢复超时非零两个开关。
- 日志增加 boot counter 和 timeout，便于确认恢复决策。
- RTD 侧提取 `should_sync_last_known_own_block` 作为最小可测试决策函数；行为与上游补丁一致，没有引入新配置或 feature。
