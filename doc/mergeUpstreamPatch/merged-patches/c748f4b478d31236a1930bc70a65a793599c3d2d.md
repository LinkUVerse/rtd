# c748f4b4：固定共识验证器使用的 epoch store

- 上游提交：`c748f4b478d31236a1930bc70a65a793599c3d2d`
- RTD 提交：`1577e755f6dd00b1368cb508e94a5d4378819ea0`
- 上游标题：`Use a single AuthorityPerEpochStore in SuiTxValidator (#24758)`

## 基线关联

fork 基线和 RTD 的交易验证器都只保存 `AuthorityState`，并在验证交易和检查 fastpath 时重新加载当前 `AuthorityPerEpochStore`。若 epoch 恰好在验证期间切换，同一个 validator 可能读到构造时共识组件所对应 epoch 之外的新 store，混用 epoch 范围的协议配置和状态。

## 移植内容

- `RtdTxValidator` 构造器显式接收并保存 `Arc<AuthorityPerEpochStore>`。
- 普通交易验证和 fastpath 检查均使用固定 store，不再从 `AuthorityState` 动态重载。
- node 和 consensus manager 在构造 validator 时传入其已经持有的同一 epoch store。
- 单元测试调用点同步传入测试 state 的 epoch store。
